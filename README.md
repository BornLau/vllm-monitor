# vLLM 模型监控

在页面添加模型，填写 **名称、URL、API Key**，保存即可接入。支持编辑、保留或替换 Key、移除模型。配置变更不需要重启容器。

## 启动

```bash
docker compose up -d --build
```

打开 http://127.0.0.1:3000 ，点击右上角 **管理模型 → 添加模型**。

- 名称：例如 `GLM-5.3-Flash`。
- URL：例如 `http://你的服务器:8080`，带不带 `/v1` 都可以。
- API Key：没有认证就留空。编辑时留空保留原 Key，也可以显式清除。

配置立即保存，API 探测在随后刷新时使用新配置，Prometheus 通常在约 30 秒内发现新采集目标，再按 3 秒间隔采样。首次出现速率或 P50 还需要足够的请求样本。保存失败会明确提示，不会显示成功。

**已有旧版容器需要执行一次上述命令升级。升级后日常增删改模型无需重启。** Docker Compose 要求 2.24+（支持可选 `.env`）；没有 `.env` 也可以启动。


## 数据保存在哪里

| 数据 | 保存位置 | 重启后 | 保留时间 |
| --- | --- | --- | --- |
| 模型名称、URL、API Key | SQLite，容器内 `/data/models.sqlite3`，挂载 `dashboard-data` 卷 | 保留 | 直到在页面移除配置 |
| vLLM 性能指标历史 | Prometheus 时序数据库，`prometheus-data` 卷 | 保留 | 默认 30 天 |
| API 探测结果及诊断摘要 | dashboard 内存缓存 | 重新采集 | 当前快照，尚无历史持久化 |

移除模型只停止后续采集并删除配置，不删除历史指标；历史按 Prometheus 的保留策略到期。改名或更换 Key 保留指标身份；更换 URL 创建新的节点指标身份，避免把旧地址的数值显示为新地址状态。页面打开后自动从 Prometheus 加载所选范围的历史，再接上实时更新；支持 2 分钟、15 分钟、1 小时、6 小时、12 小时和 24 小时，刷新页面无需重新累积。历史仅覆盖实际已采集的时间，未采集的区间不会补造数据。

`docker compose down` 保留两个数据卷；**`docker compose down -v` 会删除配置与历史指标**。备份模型配置时可停止 dashboard 后复制 SQLite 文件；备份 Prometheus 请使用其快照流程或停机备份整个数据卷。

API Key 存储于服务端 SQLite，文件权限为 `0600`；不回显到页面、不写入状态 API、服务发现或导出摘要。当前 Key 未做应用层加密，数据库文件及备份应按凭证管理。`data/` 和 `.env` 均被 Git 忽略。

## 原有配置如何迁移

新数据库首次启动时自动导入 `.env` 中的 `MODEL_n_NAME / MODEL_n_URL / MODEL_n_API_KEY`，没有这些变量时兼容导入 `services.json`。后续以数据库为准，不再从环境变量覆盖页面编辑；即使把所有模型删除，重启也不会重新导入。旧 `.env` 中不再需要的模型变量可在迁移后删除。

项目不再附带环境变量或旧版配置示例，新用户直接在页面配置即可。旧版 PD / 自定义端口或不同 metrics Key 的配置会保留采集能力；简化表单不支持编辑复杂配置，可移除后按单入口重新添加。容器若要首次导入旧 `services.json`，需挂载文件并设置 `SERVICES_CONFIG`。

## 自动监控哪些内容

| 接口情况 | 面板内容 |
| --- | --- |
| `/v1/models` 可访问 | API 在线状态、认证结果、探测响应时间 |
| 同一端口还开放 `/metrics` | KV、等待队列、运行请求、吞吐、首字延迟等 |
| 没有 `/metrics` 或采集未就绪 | 性能显示 `—`，API 状态独立展示 |

同一个 Key 用于 API 和 metrics，不跟随重定向。带代理前缀如 `/model-a/v1` 时，对应指标地址为 `/model-a/metrics`。如果实际 metrics 使用其他端口或另一把 Key，简化模式只能看到入口连通性。

PD 分离先按单入口监控，不自动推断背后的节点状态。只有网关主动提供各节点状态或带节点标签的聚合指标，才可能通过一个端口观察内部节点。参考 [vLLM PD 说明](https://docs.vllm.ai/en/latest/features/disagg_prefill/)。

- `/models` 探测不产生推理请求，不证明特定模型能够成功生成；探测耗时不是生成延迟。
- 每个配置对应一个服务端点；同一 URL 后面路由多个模型时，本版不拆分它们的指标。
- 输出 tok/s 改为「解码速度」：`1 / histogram_quantile(0.95, …request_time_per_output_token_seconds_bucket…)`。请求级 TPOT =（请求总耗时 − TTFT）/（输出 Token 数 − 1），排除首 Token 等待时间；与页面请求级 TPOT P95 互为倒数，表示单请求解码速度，不是并发总吞吐。输入 tok/s 仍为输入 Token 增量 ÷ 采样间隔。只有确认有活动的采样段展示性能数值；空闲时显示 `—`，趋势图以零基线连接（仅表示空闲，不代表实测解码速度或延迟为零）。活动未知、采集失败及缺失观测显示断点。
- 活动判定综合运行数、等待数、输入/输出 Token 增量、请求完成及首 Token 观测增量；任一大于零即保留，因此运行数为零但刚完成的短请求不会丢失。所有判定信号齐全且为零才标为空闲，缺失时为未知。运行/等待数、KV、负载不均等当前状态和近 1 小时抢占次数仍如实展示；Prometheus 原始数据保留，过滤作用于性能数值展示；历史曲线与实时曲线采用相同的空闲基线规则。活动判定仍使用原始 Token 计数器，不依赖 TPOT 指标；请求尚未完成时也能判断活动状态。
- 延迟分位数与前缀缓存命中率只统计最近两次采样间新增的观测；无新增观测显示 `—`，不会保留旧负载的统计值。P50 / P95 是直方图估算分位数，不是单次请求延迟。抢占仍为近 1 小时累计次数。
- 输入速率和 TPOT 桶增量使用 `irate(...[1m])`：1 分钟仅是查找最近两个采样点的范围，不是平均窗口。TPOT 仅在请求完成时记录；缺少请求级 TPOT 指标、无新增观测或 TPOT 非正时，解码速度显示 `—`，不回退到总吞吐或 ITL。分位数受桶宽影响；只有桶数据时无法精确剔除输出不超过一个 Token 的零 TPOT 请求，这些样本可能使估算速度偏高。
- 指标依据 [vLLM 官方文档](https://docs.vllm.ai/en/latest/usage/metrics/)，不同版本可能不完整。节点分位数不相加。TPOT P95 倒数表示偏慢请求对应的速度，不是速度分布的 P95。

## 本地开发与访问

```bash
ALLOWED_HOSTS='*' BIND_ADDRESS=0.0.0.0 python3 dashboard/app.py
python3 -m unittest discover -s tests -v
node --test tests/*.cjs
```

用 Prometheus 的查询引擎验证 TPOT P95 倒数（需安装 `promtool`）：

```bash
python3 tests/promql_decode.py > /tmp/vllm-monitor-decode-tests.yml
promtool test rules /tmp/vllm-monitor-decode-tests.yml
```

数值用例使用短窗口，覆盖分位数倒数、并发聚合、计数器重置、缺失指标、零 TPOT、无完成请求、过期样本及采集失败。

Python 3.9+，仅使用标准库。本地数据库默认是 `data/models.sqlite3`，可用 `CONFIG_DB` 改位置。本地对接 Prometheus 可设置 `PROMETHEUS_URL=http://127.0.0.1:9090`。

端口仅发布到宿主机回环地址；配置写入带请求校验与跨站保护，**没有内置用户登录**。远程用 SSH 转发：

```bash
ssh -L 3000:127.0.0.1:3000 用户名@服务器
```

如使用已有认证的反向代理，需将访问域名加入 `ALLOWED_HOSTS`（逗号分隔，不含端口），并保留 `dashboard` 以便容器内采集发现。默认允许 `localhost,127.0.0.1,::1,dashboard`。

### 多模型布局

模型数量没有两个的限制，可在管理模型中连续添加 5–10 个或更多模型。首页每行一个模型，左侧关键数值、右侧四张趋势图（解码速度、首字延迟 P50、等待队列、KV Cache）。支持搜索、状态筛选、排序、暂停、历史范围切换与展开诊断；窄屏自动排列为两列图表。

### 流式趋势

默认每 3 秒读取一次状态，可用 `REFRESH_SECONDS` 配置（最短 3 秒）。Prometheus 默认每 3 秒采样一次，采集超时为 3 秒，仍按自己的采集间隔更新，页面刷新不等于底层产生新样本；输入吞吐、解码速度、延迟分位数和缓存命中率基于最近两次采样，历史范围切换只影响图表显示范围，不改变指标计算。实时监控四张趋势图均使用经过采样点的平滑曲线，保留峰值；只有两个连续有效点时使用直线连接。图表按实际快照时间向左移动，最多延后一轮显示以平滑衔接；断点判定会容纳一次正常的上游采集耗时。历史由 `/api/history` 从 Prometheus 查询，每条曲线约最多 1200 个历史取点，较长范围降低取点密度（不是对速度取窗口平均，因此可能漏掉取点之间的短峰值）；随后接入实时采样。切换历史范围会重新查询，失败会提示并重试，采集失败或缺失指标显示断点。Prometheus 原始指标仍按 30 天保留策略保存，页面内最多缓存 24 小时。

`/v1/models` 返回 404 时使用灰色“/v1/models 探测受限”提示，不把发现接口缺失当成推理服务故障；401、5xx 和指标异常仍正常提示。独立预览页面与 `/demo` 演示接口已移除。

无 Docker 的本地启动：`ALLOWED_HOSTS='*' BIND_ADDRESS=0.0.0.0 PORT=3000 python3 dashboard/app.py`。

## 镜像与网络访问

Prometheus 固定为 `prom/prometheus:v3.13.3`（3.13 LTS）；Python 保持原来的 `python:3.12-alpine` 浮动标签。版本依据：[Prometheus LTS](https://prometheus.io/docs/introduction/release-cycle/)、[Python 官方镜像清单](https://github.com/docker-library/official-images/blob/master/library/python)。

Compose 默认将监控页面发布到 `0.0.0.0:3000`，通过 `http://服务器IP:3000` 访问。`ALLOWED_HOSTS` 默认为 `*`，接受各机器地址；可在 `.env` 中改成指定域名/IP列表。页面没有登录认证，可达该端口的用户能管理配置。Prometheus 9090 仍只发布到本机。

模型管理支持选填“显示别名”，实时监控及统计图表优先显示别名；留空使用原名称，不改变采集标识或历史数据归属。

### 用量统计

点击首页「用量统计」进入 `/stats`（兼容旧地址 `/statistics`），查看请求处理总数、输入 / 输出及合计 Token 总量和分模型明细。默认近 30 天，可切换今天、近 7 天；点击刷新更新统计。统计当前配置入口，保留底层 `model_name` 标签，同一入口的不同模型分别显示。

数据来自 `request_success_total`、`prompt_tokens_total`、`generation_tokens_total` 的 `increase`，先处理各计数器重置再聚合。数值是历史采样范围内的估算量，四舍五入显示，不是 tok/s，也不是永久累计账本；接入前用量、保留期外历史及采集缺口无法完整恢复。缺失数据不计零；部分缺失时总计与柱状图汇总已知用量并提示不完整，全部缺失时显示 `—`。跨入口或 PD 多节点可能重复观测同一请求，当前按入口分别计数，不做请求级去重。

统计页的「平均时延」默认显示近 24 小时，支持近 6 / 12 / 24 / 48 小时、7 天及自定义时间。每个模型一行展示 TPOT 和 TTFT 两张延迟曲线图，单位为毫秒；水平虚线标注所选范围的有效采样均值。TPOT 使用请求级每输出 Token 耗时直方图，TTFT 使用首 Token 延迟直方图，两者均用最近两次采集间的 sum 增量除以 count 增量，表示新增观测的实际平均耗时，不使用分位数，也不代表逐条请求原始耗时。虚线对每 3 秒有效采样求时间均值，不是请求加权均值。无新增观测、采集失败、过期或不完整的 sum/count 指标排除，缺测处断线，有效零值保留。均值标注在纵轴上，横轴展示整点刻度，曲线下方使用淡色填充。趋势图按时间桶聚合全部有效的 3 秒采样，每条曲线最多约 288 个点，近 24 小时使用 5 分钟时间桶，末尾不足一个桶的区间单独统计；平滑曲线连接相邻有效桶；只有空桶内每个评估点均确认采集正常且无新增时延观测、前后有效点相距不超过 30 分钟时，才以实线插值连接并标注灰底。灰底悬停说明插值不参与均值计算，长间隔、采集异常和未知状态保持断点。均值以橙色虚线加白色衬底置于曲线上层。纵轴随有效数据及均值自动收紧，上下保留少量空白，不固定从零开始；恒定值保留最小显示范围。桶内均值可能平滑短峰值；虚线仍按完整 3 秒采样计算。修改采集间隔时应同步调整 `AVERAGE_STEP`。

统计图按北京时间自然日汇总，横轴为日期，纵轴为请求数或 Token 量，按模型堆叠；今天是未结束的部分日期。顶部总计为日期范围内已知日数据之和，缺失日标记为缺失、不补零。排队趋势为各模型每日平均排队请求数（包含零值采样），缺失日断线；不代表排队峰值或累计排队次数。所选时间范围的 TPOT / TTFT 趋势与均值独立展示。

每日图表日期轴下方提供带全量缩略图的日期刷选条，拖动两端选择日期区间，拖动选区整体平移。主图始终适配窗口宽度，三张日图与顶部累计数字实时同步更新；模型搜索只影响图表，平均时延的时间范围独立不变。

实时曲线的实线与填充只表示有效采样；缺测间隔使用虚线连接，末尾虚线为最近有效值参考，不代表当前实测值，不参与统计。历史查询与实时采样时间戳错位时，以实时采样覆盖的时间段为准，避免历史空值插入造成假断线。

平均值的自定义时间按浏览器本地时区输入，支持 3 秒至 30 天的起止范围，结束时间不能晚于当前时间。选择后点击「刷新平均值」查询；有效采样占比按实际选择的时长计算。

每日用量柱状图的悬浮提示以两栏大号数字展示该模型当日请求数和 Tokens，保留日期、模型和项目信息，不展示节点信息。
